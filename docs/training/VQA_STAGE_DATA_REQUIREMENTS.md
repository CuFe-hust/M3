# 当前阶段训练数据需求：VQA 优先的遥感任务能力

## 1. 当前目标

当前阶段训练 Qwen3-VL-8B 在不依赖专用检测器或其他子 Agent 的情况下，能够作为遥感任务的通用兜底模型，优先提升 VQA 能力。

本阶段的核心验收对象是最终文本答案与标答的匹配程度。为了使答案建立在可验证的视觉证据上，训练目标同时要求模型以文本坐标输出与问题相关的目标框；框的可视化由确定性后处理完成，不属于模型训练目标。

当前参数方案假设为：

- 使用已经完成遥感视觉—文本对齐的 checkpoint；
- 冻结 Vision Encoder；
- 全参数解冻主 vision-language merger 与 DeepStack 专用 merger；
- 在 LLM 的 Attention 和 MLP 投影层挂载 LoRA；
- merger 与 LLM LoRA 使用不同的学习率，具体值由后续实验确定。

## 2. 本阶段不训练的能力

以下能力与 VQA 任务完成能力分开，留到后续阶段：

- 首次 Qwen 调用中的 `task + visual plan` 联合规划；
- 是否调用工具、选择何种工具以及多轮工具轨迹；
- 基于 1080p 缩略图预测裁切 ROI；
- 对工具返回结果进行复核、重试或调整计划；
- 完整覆盖变化描述、变化问答和其他非 VQA Agent。

本阶段可以使用 grounding 作为 VQA 的基础能力监督，但不把 Planner 或工具调用协议混入相同训练目标。

## 3. 需要的数据能力

### 3.1 文本到 Grounding

需要“图像 + 文本目标表达 → 目标框”的单向数据，用于建立通用的目标定位能力。

应保留：

- 指代短语到单个或多个目标框；
- 带属性的目标表达，如颜色、大小、方向、类别和相对位置；
- 同类多实例目标；
- 小目标、密集目标、部分遮挡目标和靠近图像边界的目标；
- 目标不存在的负样本，输出空框集合。

应排除：

- 输入框、输出类别或描述的 Grounding → 文本数据，例如 GeoChat `[identify]`；
- 需要模型从框反向识别目标的样本；
- 坐标缺失、坐标不可解释或图像与标注无法可靠对应的样本。

对于同时包含文本描述和多个嵌入框的 grounded caption 数据，只有在能够确定性拆成“目标文本 → 对应框”样本时才进入本类；不得依靠模型或不稳定启发式方法猜测文本与框的绑定关系。

### 3.2 带框的 VQA

这是本阶段最重要的数据类型。每条样本同时监督：

1. 找出回答问题所需的视觉目标；
2. 以文本坐标输出目标框；
3. 根据这些目标给出最终答案。

各类 VQA 所需的框监督如下：

| VQA 类型 | 所需视觉监督 | 最终答案 |
|---|---|---|
| 计数 | 所有符合条件的实例框 | 规范化整数文本 |
| 存在性 | 正样本中的相关目标框；负样本为空框 | `Yes/No` 或数据集规定形式 |
| 数量比较 | 两组被比较对象的实例框，并保留组别标签 | 比较结论 |
| 位置/空间关系 | 目标对象及必要参照对象的框 | 位置或关系文本 |
| 类别/颜色/形状/大小 | 被询问对象的框 | 对应属性文本 |
| 场景分类 | 仅在存在明确局部证据时提供框 | 场景类别 |
| 整体推理 | 提供结论真正依赖的对象框；没有局部目标时允许空框 | 简洁推理结论 |
| 多项选择 | 与问题相关的目标框 | 规范化选项或选项文本 |

计数数据必须满足：

```text
有效实例框数量 == 最终计数答案
```

无法逐实例标注的 crowd、区域面积估计或含糊数量样本不能伪装成严格实例计数数据，应单独标记或排除。

### 3.3 只有答案的 VQA

没有可靠框标注的高质量 VQA 仍然可以用于扩大任务覆盖，包括场景理解、影像属性、开放推理和不易局部化的问题，但不能替代带框 VQA。

这类样本的作用是训练答案映射和领域推理；它们不能证明模型已经学会实例定位。训练数据中必须能区分：

- `grounded_vqa`：框和答案均有监督；
- `answer_only_vqa`：只有答案监督；
- `holistic_vqa`：问题本身不应强制产生局部框。

不得为补齐格式而给 answer-only 样本生成未经验证的伪框。

### 3.4 困难样本与反例

仅使用普通正样本容易使模型学习答案先验。当前阶段需要覆盖：

- 零目标计数和不存在目标；
- 一个目标与多个目标；
- 密集、稀疏以及数量跨度较大的场景；
- 外观相似但不属于目标类别的干扰物；
- 相邻、重叠、截断和尺度差异明显的实例；
- 限定区域、限定属性或限定子类别后的计数；
- 问题描述的目标在图中不存在；
- 同一图像上的不同问题，避免模型只根据整图记忆固定答案；
- 不同图像上的近似问题，避免模型只根据问句模板预测答案。

## 4. 推荐的训练目标格式

训练记录应保留原始问题和答案，并生成独立、可追溯的训练视图。建议的最小回答结构为：

```json
{
  "boxes": [
    {
      "label": "commercial building",
      "xyxy": [120, 85, 236, 214]
    }
  ],
  "answer": "1"
}
```

要求：

- 坐标为文本数字；
- VQA/Agent 证据框统一使用整图左上角原点的 `0..999` 归一化 `xyxy`；
- `x1 < x2` 且 `y1 < y2`；
- 所有框必须引用模型实际看到的图像坐标系；
- `label` 表示该框在当前问题中的角色或目标类别；
- 最终答案使用评测所需的规范形式；
- 不输出隐藏推理过程。

训练数据的规范结构可以在导出阶段映射为实际部署所需的严格响应 Schema，但训练与推理所见的字段语义、坐标制式和回答形式必须一致。

## 5. 几何标注处理

原始 Ground Truth 必须只读保留。训练视图中的坐标转换需要记录来源和变换方式。

- 原始 axis-aligned box 可以确定性归一化到 `0..999 xyxy`；
- 原始 OBB/polygon 不得静默当作 `xyxy`；
- 如果为了注意力证据或裁切生成 enclosing AABB，应标记为派生框，并保留原始 OBB/polygon；
- 派生 AABB 不能被描述为与原始官方 grounding 指标等价；
- 缩放、裁切或 padding 后必须同步变换坐标，并做越界和退化检查；
- 无法可靠完成坐标变换的样本不得进入带框训练集。

本阶段的 VQA 实例框与后续 Planner ROI 是不同语义：实例框描述问题相关对象，Planner ROI 描述下一轮需要裁切的注意区域。两者不得共用同一个未区分的标签。

## 6. 当前数据源的使用边界

### VRSBench

可用于：

- 开放 VQA；
- 计数、存在性、位置、类别、颜色、场景、形状、大小、推理、城乡和方向；
- referring 文本到 grounding；
- 在标注能够可靠绑定时构造带框 VQA。

官方 train 数据可进入训练；既定 eval/test split 必须冻结。

### GeoChat

可用于：

- `[refer]` 文本 → grounding；
- 计数、存在性、比较、位置、颜色、推理和场景分类；
- 能够由同图可靠目标标注构造的带框 VQA。

需要排除：

- `[identify]` 等 Grounding → 文本样本；
- 无法确定文本与框绑定关系的混合标注；
- 已知坐标异常且无法确定性修复的记录。

### MME-Realworld-RS 与 XLRS-Bench

本阶段作为外部分布评测使用，不进入训练。它们用于判断模型是学会了可迁移的遥感 VQA 能力，还是只记住 VRSBench/GeoChat 的问题模板与图像分布。

### LEVIR-CC / ChangeChat

变化理解不属于当前 VQA 优先阶段的核心训练数据。应保留其原始 split，待后续变化 Agent 能力阶段单独处理，不在本阶段为了增加样本量而混入。

## 7. 数据质量门槛

一条带框 VQA 在进入训练前至少应通过：

- 图像可读取且与标注对应；
- 问题、答案和目标框语义一致；
- 坐标有限、合法且位于声明坐标系；
- 框标签与问题中的目标条件一致；
- 计数答案与有效实例数一致；
- 负样本不包含虚构框；
- 不含 Ground Truth 泄漏、数据集内部路径或机器绝对路径；
- 严格 JSON-safe；
- 同一原始图像不得跨 train/validation/test 泄漏；
- 重复问答和高度模板化样本能够被识别并控制权重。

任何清洗、过滤、坐标转换和答案规范化都应生成派生训练视图，不覆盖源标注。

## 8. 本阶段建议形成的三个数据子集

```text
1. text_to_grounding
   图像 + 目标文本 -> 目标框

2. grounded_vqa
   图像 + 问题 -> 相关实例框 + 最终答案

3. answer_only_or_holistic_vqa
   图像 + 问题 -> 最终答案，局部框为空或不可用
```

第一类教授定位原语，第二类是当前阶段核心，第三类补充无法用实例框表达的遥感理解与推理能力。具体采样比例、课程顺序和各数据集权重在完成数据审计后另行确定。

## 9. 后续阶段需要另行准备的数据

本阶段稳定后，再准备以下独立数据：

- `缩略图 + 问题 -> task + visual plan`；
- 大图缩略图上的 ROI 标注及原图裁切映射；
- `plan -> tool call -> tool result -> final answer` 多轮轨迹；
- 工具不需要调用、工具失败、空结果和纠错样本；
- counting、grounding、change、caption 等其他 Agent 的专门兜底数据。

这些数据不应提前混入当前 VQA 能力实验，否则难以判断性能变化来自领域任务学习、规划学习还是工具协议学习。
