# 14B — VQA 子工作流冻结方案

> Status: frozen design decision; no production implementation yet.
> 状态：设计已冻结；尚未进入生产实现。

## 1. 文档目的

本文用于团队同步第一次 Qwen 规划之后的 VQA 子工作流，冻结目前已经确认的
VQA 分支、ROI、类别目录、YOLO、SegFormer、逐类别回退以及最终 Qwen 输入规则。

本文是
[`14_FIRST_QWEN_VISUAL_WORKFLOW_PLAN.md`](./14_FIRST_QWEN_VISUAL_WORKFLOW_PLAN.md)
的下层决策，并取代该文档及
[`14A_FIRST_QWEN_VISUAL_WORKFLOW_IMPLEMENTATION_PLAN.md`](./14A_FIRST_QWEN_VISUAL_WORKFLOW_IMPLEMENTATION_PLAN.md)
中与以下内容冲突的早期设想：

- 独立的 `mask_evidence_vqa` 主分支；
- 按目标类别分别调用 YOLO；
- YOLO/SegFormer 正常空输出不回退；
- 在 ROI 图上绘制编号检测框；
- 向最终 Qwen 暴露检测置信度；
- 跨 ROI 融合为唯一 SegFormer 掩膜；
- 使用 `0..999` 作为 ROI 输出坐标。

本文不表示相关生产代码已经存在。实施仍须遵守仓库白名单、包边界、测试、
artifact、resume、模型构造与评测保护规则。

## 2. 适用范围与基本前提

本文只定义 VQA Agent 内部的子工作流，不把其最终 Qwen 输入形式推广到 Caption、
Grounding、Change、Counting 或通用兜底 Agent。

基本原则：

```text
不同 Agent 可以有不同的最终 Qwen 输入契约；
同一 Agent 的不同子工作流也可以有不同的最终 Qwen 输入契约。
```

本文假设系统已经存在一个可以按指定区域自由裁切原始图片的工具接口。本文定义
它必须遵守的几何语义，但不实现该工具。

## 3. VQA 最终分支

VQA 只保留两个一级子工作流。

### 3.1 `object_evidence_vqa`

适用于需要物体类别或位置证据辅助回答的问题：

```text
第一次 Qwen 规划
  -> 组合类别与语义注意 ROI
  -> 版本化类别目录展开叶子类别
  -> 每个 ROI 执行一次 YOLO 完整推理
  -> 按请求叶子类别筛选 YOLO 输出
  -> 仅未筛选到结果的叶子类别进入 SegFormer
  -> 每个 ROI 执行一次所需的 SegFormer 完整推理
  -> 按缺失叶子类别筛选 SegFormer 输出
  -> 最终 Qwen 只调用一次并综合全部已有证据作答
```

### 3.2 `direct_vqa`

适用于不需要物体检测证据的问题。场景分类、城乡判断、环境条件、住宅区或工业区
等高层场景语义直接进入该分支，不以 SegFormer 作为主判断模型。

```text
第一次 Qwen 规划
  -> 干净全图或语义注意 ROI
  -> 最终 Qwen 直接作答
```

不再保留独立的 `mask_evidence_vqa` 一级分支。SegFormer 只存在于
`object_evidence_vqa` 的缺失类别回退层。

## 4. 第一次 Qwen 的下游职责边界

第一次 Qwen 只负责声明：

- 是否需要物体检测证据；
- 需要哪些封闭组合类别，去重后最多三个；
- 问题是否存在明确、可靠的语义空间约束；
- 最多三个语义注意 ROI。

第一次 Qwen 不负责选择 YOLO、SegFormer、checkpoint、阈值或 backend，也不负责
把某个类别绑定到某个 ROI。

ROI 只表达问题级语义位置，例如“左上角”或“图中的城市区域”，不表达
“飞机使用 ROI-1、船使用 ROI-2”这样的目标级映射。所有请求类别都从所有 ROI
的完整模型输出中统一筛选。

## 5. 唯一类别目录

系统维护一个版本化、封闭的类别目录，作为以下内容的唯一事实来源：

```text
组合类别
  -> 叶子类别集合
  -> 叶子类别到 YOLO 输出标签的映射
  -> 叶子类别到 SegFormer 输出标签的映射
```

第一次 Qwen prompt、输出校验、组合类别展开、模型能力判断和结果筛选必须读取同一
目录版本。模型训练或标签调整时更新目录和版本，不在工作流中增加 model-specific
条件分支。

组合类别必须保持真实语义关系。例如：

```text
vehicle -> small_vehicle + large_vehicle
```

`ship` 不属于 `vehicle`，不得为了复用 detector 建立错误上位关系。

目录外组合类别的最终容错策略尚未冻结，见第 16 节；coding agent 不得自行猜测。

## 6. ROI 契约

### 6.1 默认行为

- 没有明确空间约束时，第一次 Qwen 应输出全图；
- 只有存在明确、可确定的位置要求时才输出局部注意区域；
- 语义区域难以可靠确定时必须输出全图；
- ROI 不与物体类别建立对应关系；
- 多个相互分离的 ROI 分开裁切，不合并成一个外接矩形。

### 6.2 数量与无效计划

一个样本最多包含三个 ROI。若 ROI 数量超过三个、坐标非法、区域退化或无法可靠
解析，则：

```text
整个 ROI 计划失效
  -> 使用原始全图作为唯一 ROI
  -> 不截断保留前三个
  -> 不再次调用规划 Qwen
```

ROI 计划失效不自动抹掉已经合法解析的类别计划。

### 6.3 规划坐标

第一次 Qwen 输出归一化 `xyxy`：

```text
[x_min, y_min, x_max, y_max]
每个值位于 [0, 1]
原点位于左上角
```

工作流先把归一化坐标映射到应用 EXIF 方向后的原始分辨率图片。为避免丢失边缘
像素，建议左上坐标向下取整、右下坐标向上取整，然后裁剪到原图边界。

1080p 预览只用于第一次 Qwen 规划，不是全局坐标基准，也不是实际裁切源。

### 6.4 上下文扩张

ROI 映射到原图后，四边分别向外扩张自身宽度或高度的 10%，再裁剪到原图边界：

```text
left/right halo  = ROI width  * 0.10
top/bottom halo  = ROI height * 0.10
```

扩张比例是可配置参数，冻结默认值为 `0.10`。实际裁切始终从原始分辨率图片进行。

### 6.5 稳定几何信息

每个 ROI 至少记录：

```text
roi_id
原图标识与原图宽高
扩张后 ROI 在原图像素坐标系中的 xyxy
裁切后 ROI 的宽高
模型输入 resize / letterbox 信息
ROI 局部坐标到原图全局坐标的完整变换
```

## 7. 图像分辨率规则

所有传给 Qwen 的图像使用同一规则：超过 1080p 才等比例缩小，不放大小图。

| 层 | 图像来源 |
|---|---|
| 第一次规划 Qwen | 不超过 1080p 的全图预览 |
| 裁切工具 | 应用方向后的原始分辨率图片 |
| YOLO / SegFormer | 原始分辨率 ROI，由模型接口自行预处理并保留逆变换 |
| 最终 Qwen | 从原图裁出的干净 ROI；若仍大于 1080p，再等比例缩小 |

没有局部空间约束时，全图本身视为一个 ROI，并按相同 Qwen 输入规则处理。

## 8. YOLO 证据层

### 8.1 调用语义

YOLO 的输入只有图片，不接收第一次 Qwen 的目标类别作为条件输入。调用次数按 ROI，
不按类别：

```text
每个 ROI 一次 YOLO 完整推理
  -> 得到 YOLO 支持标签的全部检测
  -> 使用类别目录映射筛选请求叶子类别
  -> 丢弃所有未请求类别的检测
```

因此，请求一个、两个或三个组合类别不会增加单个 ROI 的 YOLO 调用次数。

YOLO 不负责理解“最大”“最近”“左边那架”“颜色”等问题语义；它只产生具体标签
与位置。语义筛选和最终回答全部交给最终 Qwen。

### 8.2 “命中”与回退

只有从当前样本的 YOLO 实际输出中筛选出至少一个目标结果，叶子类别才算命中。

```text
目录声明 YOLO 支持该叶子类别
+ 推理成功
+ 实际筛选结果为空
= 仍然缺失，继续进入 SegFormer
```

本方案不存在 `valid_empty` 终止状态。模型支持某标签不等于当前图片已经命中该标签。

回退以叶子类别为粒度：已命中的叶子类别保留 YOLO 证据，不进入 SegFormer；只有
未命中的叶子类别继续回退。多 ROI 作为该类别的一组观察范围处理，不引入
`(leaf_category, roi_id)` 级回退状态。

### 8.3 局部与全局位置

每条最终保留的 YOLO 记录包含：

```text
具体叶子类别
roi_id
ROI 局部像素 xyxy 及对应 ROI 宽高
原始分辨率图片上的全局像素 xyxy 及原图宽高
```

局部坐标帮助最终 Qwen 对齐正在观察的 ROI；全局坐标是回答全图位置与空间关系的
权威坐标。工作流必须完成 resize / letterbox 逆变换和 ROI 偏移叠加，不让 Qwen
自行计算坐标变换。

### 8.4 阈值、去重与冲突

- 每个叶子类别使用独立、可人工校准的置信度阈值；
- 多 ROI 重叠造成的重复目标由 YOLO 证据层在全局坐标系中几何去重；
- 同一目标发生标签冲突时，以内部置信度更高的类别为准；
- 去重后只保留一条规范记录，使用胜出检测的 `roi_id`、局部坐标和全局坐标；
- 其他 ROI 中的重复记录直接丢弃；
- 置信度只用于阈值、NMS、去重和冲突裁决，不提供给最终 Qwen。

具体阈值属于后续 YOLO 训练、验证和人工校准参数，不由第一次或最终 Qwen 决定。

## 9. SegFormer 回退层

### 9.1 调用与筛选

SegFormer 只为 YOLO 未命中的叶子类别提供回退。与 YOLO 相同，SegFormer 接收
图片并产生完整语义分割结果，而不是按类别条件推理：

```text
存在 YOLO 未命中的叶子类别
  -> 对所需 ROI 执行 SegFormer 完整推理
  -> 只筛选缺失叶子类别对应的掩膜
  -> 丢弃未请求类别及已由 YOLO 命中类别的 SegFormer 输出
```

同一次 SegFormer 推理可以同时为多个缺失叶子类别提供结果，不按类别重复推理。

### 9.2 “命中”与最终视觉兜底

只有筛选出非空目标掩膜才算 SegFormer 命中。标签受支持但实际目标掩膜为空，仍然
属于缺失。SegFormer 仍未命中的叶子类别不触发额外 Qwen 证据提取调用，而是在
同一次最终回答 Qwen 中依靠干净 ROI 进行视觉判断。

### 9.3 输出形态

SegFormer 保留像素掩膜，不转换成检测框或实例数量。最终视觉证据为：

```text
干净 ROI 图
+ 同一 ROI 的半透明彩色掩膜覆盖图
+ 颜色到具体叶子类别的图例
+ ROI 到原图的几何信息
```

相同叶子类别在同一样本的全部 ROI 中使用相同颜色；固定调色表也应尽量保持跨样本
稳定。颜色只是视觉辅助，不是程序判断类别的唯一编码，最终 Qwen 不接收像素置信度。

不同 ROI 的掩膜独立保留。重叠 ROI 在同一全局像素上给出不同标签时，不在工作流
层强制融合成唯一掩膜，也不比较跨裁切的像素置信度；最终 Qwen 结合各自的干净图、
覆盖图和图例判断。

SegFormer 不承担：

- 实例级数量统计或相邻实例拆分；
- 细粒度属性识别；
- 最终场景分类；
- 复杂空间语义推理。

## 10. 最终 Qwen 输入契约

### 10.1 公共内容

最终 Qwen 始终接收：

```text
原始问题
外部任务的答案格式约束
原图宽高
每个 roi_id、ROI 原图裁切位置及 ROI 尺寸
当前 VQA 子工作流组织的视觉与文本证据
```

最终 Qwen 负责属性判断、关系理解、问题语义筛选和答案生成。已有证据不会改变
`UnifiedSample.task`、答案协议或评测身份。

### 10.2 固定图像顺序

多 ROI 输入按 `roi_id` 成组排列：

```text
ROI-1 干净图
ROI-1 掩膜覆盖图（仅当该 ROI 有 SegFormer 证据）
ROI-2 干净图
ROI-2 掩膜覆盖图（仅当存在）
ROI-3 干净图
ROI-3 掩膜覆盖图（仅当存在）
```

最多三个 ROI，因此 SegFormer 混合路径最多提供六张图。文本证据按同一 `roi_id`
顺序分组，防止干净图、覆盖图和坐标记录错配。

### 10.3 YOLO 文本证据

YOLO 证据以文本记录提供，包含具体叶子类别、`roi_id`、ROI 局部坐标和原图全局
坐标。当前方案只提供干净 ROI，不绘制编号检测框，也不提供置信度。

### 10.4 SegFormer 视觉证据

存在 SegFormer 证据的 ROI 使用“干净图 + 掩膜覆盖图”双图输入，并提供稳定的
颜色—类别图例。干净图用于观察真实颜色、纹理和细节，覆盖图用于观察类别级空间
分布；掩膜颜色不得被解释为物体真实颜色。

### 10.5 混合证据与缺失类别

不同叶子类别可以分别由 YOLO、SegFormer 和最终 Qwen 视觉兜底处理：

- 保留全部已经命中的 YOLO 文本证据；
- 保留全部已经命中的 SegFormer 掩膜证据；
- 只对仍缺失的类别提示“无结构化子模型证据”；
- 最终 Qwen 使用同一次回答调用观察干净 ROI；
- 不因某个类别缺失而丢弃或重跑其他类别的成功证据。

`object_evidence_vqa` 无论是否发生视觉兜底，都只有一次最终回答 Qwen 调用。

## 11. 状态转移表

| 当前层结果 | 该叶子类别的结果 | 下一步 |
|---|---|---|
| YOLO 实际筛选到至少一个框 | YOLO 命中 | 保留证据，不进入 SegFormer |
| YOLO 标签受支持但筛选为空 | 缺失 | 进入 SegFormer |
| YOLO 标签不支持/模型不可用/执行失败 | 缺失 | 进入 SegFormer |
| SegFormer 实际筛选到非空掩膜 | SegFormer 命中 | 保留证据 |
| SegFormer 标签受支持但筛选为空 | 缺失 | 最终 Qwen 视觉兜底 |
| SegFormer 标签不支持/模型不可用/执行失败 | 缺失 | 最终 Qwen 视觉兜底 |

这里的“只回退缺失类别”是证据保留规则，不代表按类别重复调用图像模型。YOLO 和
SegFormer 都按 ROI 执行完整推理，再按叶子类别筛选一次推理的输出。

## 12. 示例

假设第一次 Qwen 请求组合类别 `vehicle`，目录展开为：

```text
vehicle -> small_vehicle + large_vehicle
```

两个 ROI 各执行一次 YOLO。YOLO 完整输出中包含 `ship`、`small_vehicle`，但没有
`large_vehicle`：

```text
ship
  -> 未请求，丢弃

small_vehicle
  -> 实际筛选命中，保留框、局部坐标和原图全局坐标

large_vehicle
  -> 实际筛选为空，仅该叶子类别进入 SegFormer
```

SegFormer 对所需 ROI 完整推理后，只筛选 `large_vehicle` 掩膜。若仍为空，则最终
Qwen 同时看到干净 ROI、已有 `small_vehicle` 文本证据，并直接视觉判断缺失部分。
整个过程中最终回答 Qwen 只调用一次。

## 13. 模型接口边界

所有模型实现只对外暴露模型无关的单一接口。VQA 子工作流依赖协议，不依赖具体
模型类、checkpoint、processor、权重路径或 device。

模型必须在 `application` composition root 中组装并复用，不得为每个 ROI、类别、
样本或请求重复加载，也不得复制 Counting 子系统已有的 YOLO loader。

工作流负责：

- 调用模型协议；
- 根据版本化类别目录筛选输出；
- 保存内部置信度用于确定性后处理；
- 完成局部到全局几何变换；
- 组装不同 VQA 子工作流各自的最终 Qwen 输入。

## 14. 已冻结决策清单

- VQA 只有 `object_evidence_vqa` 和 `direct_vqa` 两个一级子工作流；
- 场景分类直接 Qwen，SegFormer 不是独立 VQA 主分支；
- 第一次 Qwen 只输出封闭组合类别，最多三个；
- 类别目录统一维护组合展开及 YOLO/SegFormer 输出标签映射；
- ROI 只表达语义位置，不绑定类别；
- 没有可靠位置约束时使用全图；
- 最多三个 ROI，越界或无效则整体退回全图且不重试规划；
- ROI 使用归一化 `[0,1]` `xyxy`，从原图裁切并默认向四边扩张 10%；
- 所有 Qwen 图像超过 1080p 才缩小，绝不放大；
- YOLO/SegFormer 按 ROI 完整推理，再筛选请求标签；
- 未请求模型输出全部丢弃；
- 实际筛选为空属于缺失，必须继续回退；
- 回退以叶子类别为粒度，已命中类别不重复处理；
- YOLO 结果同时提供 ROI 局部坐标与原图全局坐标；
- 跨 ROI 重复检测只保留内部置信度更高的一条规范记录；
- 最终 Qwen 不看到检测或像素置信度；
- SegFormer 保留掩膜，不转框、不计实例；
- 重叠 ROI 掩膜独立保留，不做跨 ROI 像素融合；
- 同一叶子类别使用稳定一致的掩膜颜色，并提供颜色—标签图例；
- 最终输入按 ROI 采用干净图在前、覆盖图在后的固定顺序；
- 子模型证据缺失不触发额外 Qwen 调用，最终回答 Qwen 始终只调用一次。

## 15. 实现时必须验证的性质

后续实现至少应通过测试证明：

- 类别目录、prompt、展开和两类模型标签映射使用同一版本；
- 多 ROI 分别裁切，不合并，且数量上限和全图回退稳定；
- YOLO/SegFormer 调用次数按 ROI 而不是按类别增长；
- 任何 resize / letterbox 后的局部坐标与原图全局坐标恢复正确；
- 未请求类别输出不会进入最终 Qwen；
- YOLO 和 SegFormer 实际筛选为空会进入下一层；
- 已命中叶子类别不会随缺失类别一起重跑或被覆盖；
- 跨 ROI 重复目标只形成一条最终 YOLO 记录；
- 置信度不会进入最终 Qwen 输入或公共 trace；
- SegFormer 掩膜不会被转换成实例框或实例数量；
- 多 ROI 掩膜不被静默融合，颜色与图例稳定一致；
- 最终图像和文本证据按 `roi_id` 稳定对齐；
- Qwen 视觉兜底不会产生额外的中间 Qwen 调用；
- 所有持久化结构严格 JSON-safe、路径安全且不包含 secret、Base64 或模型 tensor；
- 不静默改变 `UnifiedSample`、TaskRouter、答案协议、确定性评测、Judge、report 或
  resume 语义。
